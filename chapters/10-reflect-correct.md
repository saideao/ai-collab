# 10 把教训写进结构（reflect + correct）：10 把教训写进结构（reflect + correct）

> 文档里的叮嘱 AI 跳过也不报错，能用结构堵住的别靠记性
>
> 在线互动版（支持勾选清单与双栏对照）：https://saideao.github.io/ai-collab/#/ep10

**对应技能卡 / 原则**：`reflect`、`correct`

## 核心要点

- **怎么想**：AI 反复犯同一个错，不是记性差，是你把教训放在了它可以跳过的地方（提示词、文档）。教训要放进结构里：最好让这个错根本犯不了。
- **怎么用**：reflect 在一件事做完后复盘，只留会改变下一次的经验，列成接受、拒绝、待办，等你批准；correct 把反复出现的错归类，按"结构 → 类型 → 检查 → 测试 → 文档"的顺序去堵，并证明新检查能抓到旧错。

## 场景引入

你有没有在提示词里，忍着火第三次敲下同一句话？

“别动测试集。”

“别动测试集。”

“我说了，别动测试集！”

每次说完它都满口答应“好的，马上改”，可下一次开新任务它照样再犯。真的是 AI 记性太差吗？这一章的两张技能卡 **reflect** 和 **correct**，给出了一个特别冷静、也特别扎心的答案。

## 为什么口头叮嘱根本没用

先给不做实验的读者解释一句什么是“测试集”：做实验评模型好坏时，必须留出一份数据只在最后打分用，平时调参数绝不许碰，否则分数就虚高作废了。

技能卡 `correct` 里，对 AI 助手的真实处境有一段极其清醒的描述：**它只看得见自己打开过的文件，会照抄离它最近的例子，并且会走能跑通的最短路径。**

你敲在某次聊天里的叮嘱，既不在它下次打开的文件里，也没人拦着它。原文紧接着补了一记重锤：**写在文档里的规则，AI 跳过了，也没有任何东西会报错。**

所以问题根本不在 AI 记性差，而在于你把血泪教训放在了一个它可以轻轻松松跳过的地方。

## 第一张卡：reflect——做完一件事就复盘

教训不该留在过眼云烟的聊天框里，那该放哪儿？先看第一张卡 **reflect（复盘）**。

一件事做完后调用它，它会把整段对话从头读一遍，专门捞四样东西：你纠正过它的地方、它自己踩过才摸索出来的坑、它本来自己就能查到却反过来问你的信息，以及那些嘴上说查了、其实没在真东西上跑过的检查。

但复盘不是什么破事都往规则里塞。一条经验想留下来，必须同时过三道门槛：**半年后依然成立、会真正改变下一次的做法、能落到某张具体的技能卡上。**

梳理完后，它会排成三栏交给你审：**接受、拒绝、待办**，等你点头批准了才改文件。而且有一条硬规矩：**凡是能用脚本自动检查的，放进待办，不写成文字规则。** 整个过程绝不往网上推送，也不开变更申请，所有改动安安静静留在你自己电脑本地。

## 第二张卡：correct——把常犯的错变得根本犯不了

如果某一个错已经反复出现好几次，光复盘改提示词还不够，这时候就该请出第二张卡 **correct**。

它会先翻项目里的修改历史、撤回记录和评审意见，把犯过的错分门别类。原文定了个明确的起跑线：**同一类错出现过两次，才算数。**（出现一次可能是偶发，出现两次就是隐患。）

归完类之后，它按一份**从硬到软的五层台阶**往下堵漏洞：

1. **改结构（最硬）**：从流程或目录结构上让这个错根本犯不了；
2. **用类型约束**：在代码类型层面把非法状态写死，写错直接编不过；
3. **加自动检查**：加一条校验规则，一犯错直接弹红字并在报错里写明该怎么改；
4. **写行为测试**：用自动化测试守住底线；
5. **写文档或提示词规则（最末）**：逼不得已才靠文字提醒。

回到开头“别碰测试集”的例子：在提示词里一遍遍叮嘱，排在最低那一层；而把测试集隔离开、让调参脚本从结构上压根读不到测试集目录，就是最高那一层。

`correct` 还有两条特别狠的收尾规矩：第一，**每加一个新检查，都要证明它真的能抓住一次以前实际犯过的旧错**——没见过失败的检查，等于没装；第二，它会维护一张规则对照表，把每条规矩和“靠什么强制保证它”配对，哪条规则后面是空的，就说明它目前还只是一句随时会被跳过的口头叮嘱。

## 跑一遍 correct 会看到什么

举个例子：如果你在一个练习项目里跑一遍 `correct`，它会先顺着历史记录把反复出现的错归成几类，然后对每一类摊开方案——挑了哪一层来堵、为什么更高一层行不通，再逐类落地修复。

需要特别留意的是，按原文规定，`correct` 动手修的时候每一类会单独做一次本地提交（commit）。所以第一次试用时，一定要拿一个小的练习项目练手，别一上来直接动你正在交稿的大课题。

（哪怕你平时不写代码，这套“五层台阶”的思维也照样好使：与其每次提醒 AI 别碰某份原始文件，不如干脆别把那份文件放进它能打开的文件夹里。）

## 核心小结

这个习惯练久了，你会从一个靠反复叮嘱和好记性兜底的人，变成一个懂得把教训沉淀进结构里的人。

## 原文精要：为什么这么写

| pstack 原文 | 白话意思 | 为什么要这么写 |
|---|---|---|
| `sees only the files it opened, copies the nearest example, and takes the shortest path that compiles（correct）` | AI 只看得见打开过的文件，照抄最近的例子，走最短的路 | 按这个假设去设计，教训才放得对地方 |
| `Nothing fails when an agent skips them.（correct）` | 文档里的规则，跳过了也没东西报错 | 所以文档排在最后 |
| `A class counts once it has happened twice.（correct）` | 出现两次才算一类 | 一次可能是偶然 |
| `Prove each new check fails on a real past mistake.（correct）` | 新检查要能抓到真实犯过的错 | 没见过失败的检查，什么也证明不了 |
| `Keep a finding only if it will still hold in six months, would change what a future agent does, and routes to a skill the session used.（reflect）` | 半年后仍成立、会改变下次、能落到一张技能卡 | 只留真正有用的，不堆规则 |
| `What a lint, script or check could enforce goes to the backlog, not into prose.（reflect）` | 能用检查做的，进待办，不写成文字 | 和 correct 同一个思路 |
| `Never open a PR or push.（reflect）` | 不推送、不开合并请求 | 改动留在你本地，由你决定 |

## 实操清单

- [ ] **1. 第二次就动手**：同一个错出现第二次。（*为什么*：原文两次算一类；再等，叮嘱只会越来越长。）
- [ ] **2. 做完用 reflect**：批准前看清每条要改到哪张卡上。（*为什么*：一次奇怪的对话不是规律。）
- [ ] **3. 反复的错用 correct**：先问能不能让它根本犯不了。（*为什么*：越高的层越不需要谁记得。）
- [ ] **4. 让它证明**：新检查要能抓到一次旧错。（*为什么*：没见过失败的检查等于没有。）
- [ ] **5. 工具差异**：reflect 要读完整对话，有的工具能自己找到聊天记录，找不到就只用当前对话；不支持技能卡的工具把全文复制进对话开头；correct 会提交改动，第一次建议先在练习项目里试用。（*为什么*：读到的对话越少，复盘能挖出的经验就越有限，先弄清工具边界才好选用法。）

# Fix Root Causes（原则：修根本原因）

> **简介**：调试排错时应用。顺着每个症状一路追查到系统第一次出错的地方，并在那里修复。只有当触发的状态本身是合法正常的时候，加保护判断才算修复。

修出错的源头，不要只修症状冒出来的地方。根本原因，是系统第一次做了不该做的事、或者没处理好它本该处理的状态的那个地方。

- **先复现。** 不断追问“为什么”，直到答案落到代码里某个错误决定上。卡住时，加观测埋点，读取真实状态。
- **先问触发症状的那个状态合不合法。** 如果状态是正常的，就在代码出错的地方妥善处理；如果这个状态本就不该存在，在下游加个检查只是把 bug 藏起来了，必须顺藤摸瓜找出是什么制造了它。加判断挡住、失败重试、吞掉报错、把超界值硬截断、直接丢掉异常状态，都是藏 bug 的常见手法。
- **修一类模式，不只是修这一个例子。** 找出所有犯同样毛病的地方一起修。
- **如果查出决定性事实费了很大劲**，提议加一个低成本、常开的信号，让下次一眼就能看见。

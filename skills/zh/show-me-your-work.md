# show-me-your-work（把你的过程给我看）

> **简介**：为长任务或无人看管的任务维护一份可审计的决策轨迹：一张 TSV 日志表，一行一个决定（做了什么、为什么、证据指针、结果）。默认留在本地，仅在评审者需要借此信任结果时提交。

全程只维护一份规范的决策日志。

## 格式说明

单一 TSV 文件，一行一个决定。每个单元格保持单行。**证据是一个指针，不是一段话。**

复制 `references/decision-log-template.tsv` 的表头开启一份干净的日志。包含六列：

- **ts**：ISO8601 时间戳。
- **phase**：当前阶段或工作线。
- **decision**：选了什么或做了什么，一行写完。
- **why**：用大白话写清原因；如果是某条原则驱动的，直接说清道理，不要只甩术语标签。
- **evidence**：能证明它的链接或路径（commit SHA、PR 号、`file:line`、产物/日志/截图路径），绝不写大段文字。
- **result**：结果或状态判断，如 `tests green`、`reverted`、`pixel-diff 0`、`INCONCLUSIVE`、`open`。

示例（平实直白，评审者一眼能读懂）：

```
ts	phase	decision	why	evidence	result
2026-05-24T09:02:00Z	frame	先盘点了工作量，大约 100 个组件、75 小时	开跑长任务前想先摸清规模	commit 3a9f1c2	开工前发现 5 件需要先理顺的事
2026-05-24T09:40:00Z	harness	动手改之前先给旧版本截了图	方便新旧对比，抓住任何视觉变化	scripts/snapshot.sh, baseline/	存下 120 张基线截图
2026-05-24T11:15:00Z	widget	迁移了组件样式，未改外观	控制改动幅度，确保效果完全一致	commit 7c21e0a, pixel-diff 0	外观完全一致，测试通过
2026-05-24T12:30:00Z	widget	弃用了某个助手的产出，因为它的截图是空白的	查了真实文件，没有轻信它的总结	worktree reset	已回退，收紧了下次指令
```

## 如何记一行

像跟队友口头汇报一样写每一条：大白话、具体动作，不要 AI 腔或抽象黑话（**unslop** 同样适用于日志）。

使用辅助脚本 `scripts/log.sh <logfile> <phase> <decision> <why> <evidence> <result>`，它会自动盖时间戳、首次建表头、清除多余制表符和换行，并给 `=`、`+`、`-`、`@` 开头的单元格加单引号防表格公式注入。

**只记决策点和检查点，不记每个细碎动作**：选了哪条岔路、完成一个单元及验证结果、转向或回退及触发原因、遇到的阻塞、修好的关卡。循环任务每次迭代记一行。显而易见的琐事别记。

一次完整的会话（含后续追问）算作一次 run；新接手、换助手或新开对话算新的 run。当新的 run 往已有日志里追加时，第一行 phase 写 `start`（标明此前非本轮写入的时间段，证据写本轮标识），方便审计划定边界。

## 存放在哪

默认作为本地工作产物，不提交进 git：放在工作目录的 `decisions.tsv`（多任务并行时用 `.audit/<task-slug>.tsv`）。只有当任务足够重大、评审者需要看过程才敢信结果时，再随代码一起提交。

## 铁律

- **只追加，不修改历史。** 发现之前判断错了，加一行新记录覆盖它，绝不修改或删除旧行。
- 优先使用已提交脚本产出的可复现证据，少用一次性手工证据（**encode-lessons-in-structure** 原则）。

## 收尾前：拿日志对照聊天记录自核

交差前核对日志有没有说谎。只读取当前工作区 `agent-transcripts/` 下的本轮聊天记录（不要通配扫 `~/.cursor/projects/*/` 翻到无关私人对话），逐行核对：

- 每一行是否对应一个真实发生过的决定或动作；
- 每一行的证据链接/路径能否打开，且真的支持它声称的结论；
- 凡是影响过方向的岔路、转向或放弃的方案如果漏记了，补上一行。

**改日志，不改故事。** 审计绝不编辑或删掉旧行（哪怕是一条编造的行），而是追加一条新行说明实际发生了什么，并附上真实可查的指针。

## 跨模型交叉审查（Cross-model review）

交差前，**用另一家公司的模型**启动一名子助手。**自己审自己不算数。** 它通读决策日志和本轮聊天记录，不是重做一遍活，而是扫出值得人类重点留神的风险：

- 证据薄弱或空缺的决定；
- 跳过验证、或嘴上说查了但聊天记录里没凭证的步骤；
- 事后看有风险的选择（过早拍板、范围蔓延、只掩盖表面症状）；
- 人类粗略扫一眼容易漏掉的缺口。

凡是产出决策日志的任务，最终回复末尾必须带一节 **Attention（注意）**：第一行单独写明审查模型（`reviewed by <model>`），接着逐条列出指向具体行号或时刻的提醒。“无风险提示（No flags）”是合法结果，但绝不能省掉模型名。

## 如何审阅这份日志

从头扫到尾，顺着证据指针抽查。GitHub 会自动把提交的 TSV 渲染成表格；在终端里用 `column -s$'\t' -t decisions.tsv` 可以排整齐阅读。
